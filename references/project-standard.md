## 1. 项目初始化

### 1.1 命名规范（强制）

```
<市场>.<代码> <公司名>
```

- 市场：SH（上海）/ SZ（深圳）/ BJ（北京）/ HK（香港）/ US（美国）
- 代码：数字部分（A股6位，港股5位，美股ticker）
- 公司名：全称或通用简称
- **代码+名称缺一不可，禁止用代码代替名称**

示例：
- `SH.601319 中国人保`
- `SZ.002884 凌霄泵业`
- `SH.600987 航民股份`

### 1.2 初始化步骤

```bash
# Step 1: 创建批次目录（<YYYY_MM_DD> = 本次分析实际日期，如 2026_08_15 仅为示例）
mkdir -p "<市场>.<代码> <公司名>/<YYYY_MM_DD>"/{data,input,scripts,reports/图表}

# Step 2: 复制模板文件
cp scripts/calc_penetration_return.py "项目/<YYYY_MM_DD>/scripts/"
cp scripts/verification.py "项目/<YYYY_MM_DD>/scripts/"

# Step 3: 创建骨架文件（按本文档模板，均位于批次目录内）
touch "项目/<YYYY_MM_DD>/README.md"
touch "项目/<YYYY_MM_DD>/ROADMAP.md"
touch "项目/<YYYY_MM_DD>/交付清单.md"
touch "项目/<YYYY_MM_DD>/reports/跟踪验证台账.md"

# Step 4: 项目根目录 财报更新验证.md（不存在则创建表头模板；每次分析追加一行，见 §6）
touch "项目/财报更新验证.md"

# Step 5: 写入初始内容（见下文各节模板）
```

## 4. 报告章节标准

### 4.1 龟龟独立分析模式（11章，详见 `references/report-template.md`）

| # | 章节 | 最低要求 |
|---|------|---------|
| 1 | 报告元信息 | 分析日期/框架版本/股价/市值/股本/Rf（标注来源或估计）/上市结构/数据来源/Warnings（每条编号） |
| 2 | Executive Summary | 一句话结论 + 核心数字表（OE/R/GG/II/KK/陷阱/可信度/仓位/置信度）+ 最大优势 + 最大风险 |
| 3 | 关键假设 | 6项假设表（G/支付率/利润口径/现金口径/税率/基准值）+ 每项选定值/替代值/敏感性 |
| 4 | 财务趋势速览 | 5年表（营收/净利/OCF/ROE/有息负债率/DPS/支付率/净现金）+ CAGR |
| 5 | 商业质量分析 | 6维摘要（商业模式/护城河/外部环境/管理层/MD&A/控股结构），每维结论段+输出评级 |
| 6 | 穿透回报率分析 | OE计算/分配能力/真实可支配现金表（4-5年）/R+GG+HH/分配意愿/收入敏感性4情景+逐年累积/可信度5维表 |
| 7 | 估值与定价 | 门槛II/安全边际KK/仓位推导链/价值陷阱5项表/股价位置（10年分位+目标买入价+门槛价格）/业绩下滑敏感性表/绝对估值表/基准价三锚与溢价 |
| 8 | 综合结论 | 汇总框（商业质量/穿透回报率/估值/优势/风险） |
| 9 | 投资论点卡 | 核心论点/买入理由≤5条/催化剂/持有周期/止损条件（结构化+自然语言）/事件监控/行业与宏观监控 |
| 10 | 风险提示 | 特定风险（描述+量化+对结论影响）+ 待验证事项表 |
| 11 | 数据来源与免责 | 数据来源汇总表 + 免责声明 |

### 4.2 统一调研模式（券商 10 部分格式）

当用户以「调研 …」触发统一调研时，主报告为 `reports/证券分析研究报告.md`，按券商深度标准10部分：
投资摘要 / 宏观经济评述 / 行业分析 / 公司分析 / 财务分析 / 财务预测 / 估值 / 投资建议 / 风险 / 附录。其中"估值"部分必须内嵌**穿透回报率估值（龟龟 Phase 3）**小节，"投资建议"必须同时给出券商目标价（12个月）与龟龟目标买入价/门槛价格/仓位建议。

### 5.2 图表规范

- **每张图必须有**：编号、标题、数据日期（YYYY-MM-DD）、数据来源
- **双输出**：PNG（嵌入MD报告）+ Plotly交互HTML（合集文件）
- **生成脚本**：统一由 `scripts/analyze_charts.py` + `scripts/analyze_charts_plotly.py` 生成，必须可复现
- **正文必须有解读**：图服务于结论，不堆砌装饰图；每张图在正文中至少有一段文字解读
- **颜色规范**：使用 `dataviz` skill 的调色板标准
- **分辨率**：PNG ≥150 DPI

## 6. 交付清单标准

交付清单文件（`交付清单.md`）分三节，模板见 `references/checklist-template.md`。

- 交付清单位于**批次目录**内（`<YYYY_MM_DD>/交付清单.md`），随批次初始化创建。
- 项目根目录 `财报更新验证.md` 为跨批次汇总：每次分析完成（或新财报发布后重析）追加一行，字段：分析日期/对应财报期/当前股价（A/H）/12M 悲观/基准/乐观/评级/本次财报要点/验证状态。它是技能迭代与结论验证的跨批次视图，**每个批次都必须追加**。

**交付时必须逐项核对并勾选，对话中按清单逐项输出结果（含缺失项说明），未勾选项不得宣称"已完成"。**

### 7.2 验证协议

