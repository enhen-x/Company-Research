# 项目文件架构 v3（时间批次版）— 模板与规则

> 状态：**2026-08-15 拟定**。SKILL.md / framework.md 的 B1.1 架构图已同步；`research_pipeline.py` B1 自动创建逻辑待实现（见 §6）。
> 动机：每次分析基于**当前可得财报**；新财报发布后必须重新分析。为避免覆盖历史结论、支持跨期结论验证与 skill 迭代，按**分析日期分批次**归档。
> 术语：批次 = 一次完整分析（一个 `<YYYY_MM_DD>/` 文件夹 + 根目录 `财报更新验证.md` 一行记录）。

## 1. 新架构（强制，未来批次生效）

```
<市场>.<代码> <公司名>/
├── 财报更新验证.md        # ★ 跨批次汇总：每次分析一行（日期/股价/12M三情景/财报要点/评级），模板见 §3
├── <YYYY_MM_DD>/          # 每个分析批次（文件夹名=本次分析的实际日期，如 2026_08_15 仅为示例；新财报后新建，旧批次保留）
│   ├── README.md          # 总览：评级/目标价/核心逻辑/风险/交付状态
│   ├── ROADMAP.md         # B4-B6 八步路线图
│   ├── 交付清单.md         # ★ 交付物清单（B6 交付前逐项核对）
│   ├── data/              # 原始数据：拉取清单.json / 审计报告.html / *.csv（行业适用时含 行业成本价格.csv + 审计 JSON，见 framework.md B2.2）
│   ├── input/             # 模型输入：穿透回报率_输入.json（guigui --config）/ sotp_输入.json + sotp_触发.json（平台型，见 framework.md B4.6）
│   ├── scripts/           # 复验与图表脚本：verification.py / calc_penetration_return.py / analyze_*.py
│   └── reports/           # 主报告 MD+HTML / 图表/ / 穿透回报率_输出.json / sotp_输出.json（平台型）/ 跟踪验证台账.md
└── <YYYY_MM_DD>/          # 下一批次（新财报后重新分析）
```

**放置规则（不变）**：数据只进批次内 `data/`；模型输入只进 `input/`；分析脚本只进 `scripts/`；交付报告只进 `reports/`；图表 PNG 只进 `reports/图表/`；交互图统一 `<公司名>_<代码>_图表.html`。**一切路径以批次文件夹为根**。

## 2. 批次规则

| 项 | 规则 |
|----|------|
| 命名 | `<YYYY_MM_DD>` = **本次分析的实际日期**（每次分析时动态取当天日期，非固定值、非财报期；同一天不同标的不冲突；`2026_08_15` 仅为示例） |
| 触发 | 新财报披露（季报/中报/年报）且结论可能变化 → 新建批次重新分析；旧批次只读保留 |
| 新建步骤 | ①复制上一批次 `scripts/`（复用脚本）②全量刷新 `data/`（B2 拉数）③B3 审计 ④B4-B6 分析 ⑤交付（批次内 交付清单/报告/台账）⑥根目录 `财报更新验证.md` 追加一行 + 新建「批次档案」区块（预测列=上期档案假设，实际/偏差/归因/迭代列待本期财报后填写） |
| 脚本兼容 | 脚本 `ROOT = Path(__file__).resolve().parents[1]` 指向批次文件夹，data/input/reports 同批，**无需改动即可在批次内运行** |
| 数据刷新 | 每个批次独立全量刷新（不做增量继承），保证批次内自洽可复算 |
| 台账 | `跟踪验证台账.md` 留在批次内（本批次预测 vs 下批次实际）；跨批次精简汇总走根目录 `财报更新验证.md` |
| 存量项目 | 不强制迁移；下次新财报复验时按新架构建第一批次（旧分析作为历史参考，或手工补一行基线记录） |

## 3. `财报更新验证.md` 模板 v2（项目根目录，2026-08-16 升级为「批次档案版」）

> **升级动机**（药明康德批次反馈）：v1 只记一行四要素，复验时拿不到上期预测的可复算假设（EPS/PE/概率/龟龟输入），无法把偏差归因到方法论环节，不足以支撑方法迭代。
> v2 结构：① 顶部「跨批次回测汇总表」（一行一批，快速扫描）；② 每批次一个「批次档案」区块——**预测假设 → 实际 → 偏差 → 归因 → 方法迭代动作**，为下次复验提供对照基线。

> 用途：跨财报期结论验证与 skill 迭代依据（v2 批次档案版）。
> 复验动作：①新建 `<YYYY_MM_DD>/` 批次重分析；②汇总表追加一行；③新增批次档案（预测列=上一批次档案的假设，实际列=本期财报，归因列=偏差来源，迭代列=写回 skill 的动作）；④偏差 >15% 或触发翻转点 → 更新滚动预测与评级。

## 4. 与现有流程的关系

- **G2 复验协议**：季度复验 → 若为新财报且结论可能变化 → **新建批次**重新分析；若仅数据刷新（无新财报）→ 原批次内更新台账即可。
- **G3 目标价回测**：12M 到期时在 `财报更新验证.md` "验证"列回填实际股价与评级有效性，作为框架参数校准依据。
- **交付规则**：交付对话仍按批次内 `交付清单.md` 逐项输出；新增交付项"根目录 财报更新验证.md 已追加一行"。
