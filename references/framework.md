## B. 流水线（6 个阶段）

### B1 解析与立项（自动）
- 解析公司名/代码 → 推断市场前缀（6/9→SH，0/3→SZ，4/8/92→BJ）
- **文件夹命名规范（强制）**：每次新建项目目录必须为 `<市场>.<代码> <公司名>`（如 `SZ.300498 温氏股份`），**代码与名称缺一不可**；任一缺失时由脚本自动解析（akshare 正/反向查询），解析失败则报错退出并提示补充，禁止用代码代替名称（如 `SZ.300498 300498`）
- 创建标准文件架构（见 B1.1）并生成 `交付清单.md`（见 B1.2）

#### B1.1 标准文件架构（强制，脚本自动创建，不得改变顶层结构）

```
<市场>.<代码> <公司名>/
├── 财报更新验证.md            # ★ 跨批次汇总：每次分析一行（分析日期/当前股价/12M三情景/财报要点/评级）；模板与规则见 references/project-structure-v3.md
├── <YYYY_MM_DD>/              # 每个分析批次（文件夹名=本次分析的实际日期，如 2026_08_15 仅为示例；新财报后新建，旧批次保留）
│   ├── README.md              # 总览：公司/代码/状态/评级/目标价/核心逻辑/风险/交付状态
│   ├── ROADMAP.md             # B4-B6 八步分析路线图
│   ├── 交付清单.md             # ★ 交付物清单（B1 建骨架，B6 交付前逐项核对）
│   ├── data/                  # 原始数据：拉取清单.json / 审计报告.html / *.csv（含行业补充数据）
│   ├── input/                 # 模型输入：穿透回报率_输入.json（guigui --config）
│   ├── scripts/               # 可复现脚本：verification.py / calc_penetration_return.py / analyze_*.py（模板源：skill scripts/，见 B2.1）
│   └── reports/               # 交付报告：
│       ├── <公司名>_<代码>_分析报告.md   # 主报告（MD，内嵌 PNG）
│       ├── <公司名>_<代码>_分析报告.html # 主报告（HTML 版）
│       ├── <公司名>_<代码>_图表.html    # Plotly 交互图表合集
│       ├── 穿透回报率_输出.json       # guigui --json 运行输出（与报告数字一致）
│       ├── 跟踪验证台账.md            # 预测台账+验证协议+迭代日志（本批次 vs 下批次）
│       └── 图表/                     # PNG 图（图NN_<名称>.png，≥10 张）
└── <YYYY_MM_DD>/              # 下一批次（新财报后重新分析）
```
**放置规则**：数据只进 `data/`；模型输入只进 `input/`；分析脚本只进 `scripts/`；交付报告只进 `reports/`；图表 PNG 只进 `reports/图表/`；交互图表统一命名 `<公司名>_<代码>_图表.html`。

#### B1.2 交付清单（每次交付必须按清单输出）

- B1 自动创建批次文件夹 `<YYYY_MM_DD>/`（=本次分析的实际日期）与根目录 `财报更新验证.md`（跨批次汇总表头，模板见 references/project-structure-v3.md §3），并自动生成批次内 `交付清单.md`，分三节：① B1-B3 自动产出（README/ROADMAP/拉取清单/审计报告/原始数据/复验脚本/穿透回报率脚本）；② B4-B6 分析交付物（主报告 MD+HTML/交互图表/PNG 图表/analyze_charts.py/analyze_*.py/穿透回报率输入输出/跟踪验证台账/README 更新）；③ 成稿门控确认项
- **交付规则**：B6 成稿前逐项核对并勾选；**对话交付时必须按清单逐项输出（含缺失项说明）**，清单未勾选项不得宣称"已完成"

### B3 数据审计（自动）

审计七项，输出 `data/审计报告.html`（人类阅读）和 `data/审计报告.json`（机器门控与复算）：

1. **完整性**：各表行数、年份覆盖（目标 ≥ 10 年）、最新报告期是否在 6 个月内、缺失率
2. **一致性**：
   - 三表勾稽：最新年度 归母净利（利润表）与 EPS×股本 交叉验证（容差 ±10%）
   - 归母权益（资产负债表）与 BPS×股本 交叉验证
   - 现金流：经营现金流/归母净利 含金量（异常年份标注）
3. **异常值**：营收/净利同比突变（**>50%**）或**符号反转**、BPS≤0、重复报告期、缺失关键字段——每项必须有合理解释（口径变更/重组/周期原因），无法解释的计入 Warnings
4. **分红一致性**：近 3 年 DPS×股本（按除权除息日归集）vs 现金流量表"分配股利支付的现金"（容差 ±10%）；口径差异（中期+末期合并、含偿付利息）必须标注
5. **支付率双法校验**：法1（DPS/EPS）vs 法2（分配现金/归母净利），近 3 年均值；两法偏差 >5pct 排除法1；DPS **≥3 年完全相同的数值**才触发"疑似填充错误"（2 年相同 + 支付率连续稳定 = **平滑分红政策**，非数据错误，标注即可）
6. **OCF 季节性集中度**：近 3 年 Q4 单季 OCF 占比（年报 − 三季报累计）/年报；任一年 >80% 时标注"季节性集中"，并对比历史序列——连续多年 >80% 判定"常态集中"（注明原因，不视作异常）；单年异常集中（历史 <60% 突升 >80%）必须调查
7. **行业成本—价格审计（行业适用时，B2.2 产出）**：`data/行业成本价格_审计.json` 无 FAIL（CSV 契约字段齐全、value 为正数、date 合法、无重复、cost+price 双 role、每序列 ≥3 行、来源与来源日期齐全）；独立来源 <2 计 Warnings（证据降级 L3）并在报告标注。**断点/刻度风险项（2026-08-17 新增）**：①序列观测缺口 `series_observation_gap`——相邻观测间隔 >2×频率基准（月 31 天/季 92 天/年 370 天）计 Warnings，报告必须说明缺口月份、禁止线性补齐；②`low_cost_price_date_overlap`——cost 与 price 共同观测日 <max(3, 50%×较少序列点数) 计 Warnings（图16 双线错位断点风险，报告须说明口径）；③`dense_date_grid`——观测日期 >16 个计 Warnings（横坐标刻度重合风险，须稀疏刻度并过 chart_qc 刻度检查）

#### B4.3 补强分析模块（v2.1：易遗漏项，缺一不可）

1. **周期均值窗口敏感性**（周期/修复/盈利波动大的公司必做）：按 5Y（含亏损）/8Y/10Y/修复期 4Y/最近 2Y/最近半年窗口计算平均归母净利与平均单位净利；输出“窗口 × 估值档（9/11/13x）”目标价矩阵；解释采用哪个锚及依据（如“预测单位净利 ≤ 最近已实现季度值”）；明确窗口选择对目标价的影响区间与风险含义。
2. **适用估值方法的敏感性与价值桥**：采用DCF时区分FCFF/WACC/企业价值与FCFE/Ke/股权价值，列税后经营利润或融资/税后利息、D&A、营运资本、资本开支等完整桥接，不能把孤立OCF−Capex直接视为统一口径。永续模型须折现率>g并披露终值占比；有限寿命、金融模型用各自关键变量。资本投入和下降情景须有经营依据。
3. **跨市场同行口径统一**：港股/美股同行市值按当日央行中间价折算人民币，注明市值日期、汇率与来源；PE 用同一盈利口径（如 2025 归母净利）计算；PB 注明测算或披露；禁止港元/人民币/美元市值直接并列。
4. **治理与关联交易量化**：股权结构（大股东、实控人状态、表决权）、股权纠纷/减持要有事实、概率与跟踪路径；并购/资产收购量化：交易对价、新增商誉（资产负债表商誉变动）、占净资产比例、整合里程碑（并表时点→收入贡献→产品占比）与跟踪指标（分部收入、毛利率、商誉减值测试）。
5. **风险概率方法学**：每个风险标注概率 + 方法（历史频率/情景推演/趋势外推/规模约束/事件驱动）+ 触发跟踪条件；明确“主观概率 = 历史频率 + 情景推演，非精算”，不适用于组合加总。
6. **同行历史估值对比**：对实际适用指标选同经济模型同行并统一期间、市场和口径；PE/PB有效时可画年度折线。缺少可比样本应解释而非凑数，用于判断估值收敛/分化和生命周期定价变化。

#### B4.4 穿透回报率估值（龟龟 Phase 3，基本面必做）

> 方法论与决策阈值以 `references/methodology.md` 为准（含凌霄泵业已校准示例）；本文档只列执行要点。

**输入**（单位：金额百万元、每股元、比率%）：
近5年三表、分红记录、市值/总股本/当前股价、10年复权+不复权行情、Rf。

**计算链**（全部用脚本，禁止手算）：

```text
维持性Capex H = 折旧摊销D × 系数G（轻资产0.7~0.9，需近3年Capex/D&A 依据）
Owner Earnings OE = 归母净利润C + D − H
支付率 M = 法2（分配现金/归母净利润），近3年均值；DPS连续多年相同禁用法1
真实可支配现金 AA：默认近2年均值 AA_2y，AA_all 对比；结余口径变化必须说明
粗算 R = C×M/市值       精算 GG = AA×M/市值
粗算偏差 HH = R − GG     （|HH|≥2pct → 专项调查）
门槛 II = max(3.5%, Rf+2%)   （A股；港股/美股用当地Rf+2%并标注）
安全边际 KK = GG − II     （弱周期不修正；强周期说明调整）
目标买入价 = 股价×GG/II   门槛价格 = 股价×II/GG
λ = Δ结余/Δ收入（符号不一致必须警告）；k* = GG(k*)=II 的临界收入倍数，k*<0 只作"安全边际极充裕"定性解读

成长校准轨（2026-08-21 新增，高成长标的必做）：C_fwd（前瞻盈利，证据支撑：公司指引/券商一致预期下沿/自建驱动桥，增速≤历史3年最高、净利率≤历史峰值）
→ R*_fwd = C_fwd×k_fwd×M_fwd/市值、KK_fwd、目标买入价_fwd；评级锚仍为保守轨 trailing，成长校准轨只给"成长验证买入区"与升级触发（methodology §2.1；calc_penetration_return.py 提供 net_profit_C_fwd 即输出 growth_calib 块）
```

**执行**：生成输入 JSON（字段见脚本头部文档），运行
`python scripts/calc_penetration_return.py --config 输入.json`
脚本输出：OE/R/GG/II/KK/目标买入价/门槛价格、单年（×0.7~×1.0）与逐年累积（×0.9^n）敏感性表、k*、绝对估值（EV/EBITDA、扣除现金PE、FCF收益率、净负债/EBITDA、商誉/总资产、股息率）、基准价三锚与溢价、现金流陷阱标记。

**报告必含表格**（按 guigui `report-template.md` 格式）：结余表（4~5年）、穿透回报率表、敏感性表、可信度5维表、价值陷阱5项表、绝对估值表、基准价与溢价表、股价分位表（**复权口径为主**，不复权对比并说明分红送转影响）、仓位推导链（KK→可信度→陷阱风险，缺一环降档）。**高成长标的（净利增速 >15% 或保守轨目标买入价 < 现价×0.6）必须并列输出龟龟成长校准轨**：C_fwd 来源与依据、R*_fwd、KK_fwd、目标买入价_fwd、"成长验证买入区"[保守轨目标买入价, 成长校准轨目标买入价] 与升级条款；禁止用成长校准轨推翻保守轨不建仓结论。**G 网格**（维持性Capex系数敏感性，近3年 Capex/D&A 极差 >1.0 时必出；G=0.5/0.7/0.9，含 H/OE/GG/目标买入价）必须由脚本 `g_grid` 输出（默认含），**禁止手写网格行**。

**数字可复算纪律（强制）**：报告中每个穿透数字行必须在脚本 `--json` 输出的 `reports/穿透回报率_输出.json`（**纯 JSON**）中存在；手写补充的数字行必须标注「手算/补充」并说明来源与口径（G7 逐字段核对覆盖此要求）。

**仓位锚点**（已校准）：KK≥1.5pct+可信度中+陷阱低 → 70%；KK 1.0~1.5pct+可信度中+陷阱低 → 50%；KK<1.0pct 或可信度低或陷阱中/高 → ≤30% 或观望；GG≤II → 不建仓（观望/卖出）。

**与券商估值衔接**：穿透回报率为基本面/现金安全边际纪律，行业适用的主方法与验证锚为市场/内在价值参考；若共享盈利假设须披露重叠，不计为独立安全边际。


#### B4.6 SOTP 分部估值（平台型公司强制，2026-08-22 新增）

**适用判定（先跑 `python scripts/sotp_valuation.py --detect-only` 自动检测）**：
- 触发（平台型/多估值锚）：C1 分部数 ≥3 且最大分部营收占比 ≤70%，且（C2 第二大分部占比 ≥10% 或 C3 分部营收 CAGR 极差 >20% 或 C4 存在成长/主题分部——agent 在 `input/sotp_输入.json` 标注 growth=true）。
- 典型：多元化化工平台（氟化工周期+电子特气成长+航空材料稀缺）、综合企业（金融+实业）、「现金牛+成长」双轨集团。
- 不触发：单一业务公司（最大分部 >70%，分部只是产品拆分）——此时 SOTP 可选，不强制。

**为什么必须做**：单一综合 PE/PB 会把「现金流主力（低倍数）+ 主题分部（高倍数）」揉成一个中间倍数，掩盖**现价透支/低估来自哪个分部**，也无法回答「若主题退潮估值回归多少」。SOTP 按分部估值锚加总，直接回答这两个问题。

**执行链（数字全部可复算，禁止手算）**：
1. `sotp_valuation.py --detect-only` → 写 `input/sotp_触发.json`（enabled + 触发理由）；
2. 触发后填写 `input/sotp_输入.json`（模板见脚本头部文档/SKILL.md §B4.6 输入模板）：
   - 每分部：`name / basis(net_profit|ebitda) / profit(分部盈利，亿元) / method(PE|EV/EBITDA) / peer(可比公司) / multiple(+low/high 区间) / growth / note`；
   - **分部净利/EBITDA 通常不直接披露 → 用「分部毛利 × 公司整体净利/毛利系数」估算，必须在 note 标注「手算/补充」**；倍数来源必须写可比公司与区间依据（同行 PE 分位、稀缺性溢价、周期位置）；
   - `adjustments`：净现金（+）、少数股东权益（−）、控股折价（默认 1.0，综合集团可用 0.75–0.90 并说明）、其他；
   - `net_profit_actual`（实际归母净利，用于「市场隐含整体 PE」对比）；
3. `sotp_valuation.py --dir <批次>` → 输出 `reports/sotp_输出.json`：分部价值/贡献度、EV、股权价值、每股 SOTP（+低/高区间）、现价溢价、市场隐含 PE vs SOTP 加权 PE、结论模板；
4. `build_ops.py` 把 sotp 键写入 `input/运营补充数据.json` → `analyze_charts.py` 生成**图18 分部估值SOTP**（左：分部价值贡献横条；右：每股 SOTP vs 现价+区间）；
5. 报告在既有 §6.2「SOTP 分部估值（适用时）」小节：嵌入图18 + SOTP 表（分部/盈利/倍数/价值/贡献度）+ 引用 `sotp_输出.json` 结论，并明确「分部净利估算」局限。

**结论使用纪律**：
- SOTP 与龟龟穿透回报率、券商共识并列披露（口径分离），不替代任一轨；
- 结论模板：现价 vs SOTP 中枢溢价 X%（或低于低档/高于高档）→ 识别价值贡献前二分部 → 市场隐含整体 PE vs SOTP 加权 PE 差异 → 判断「现价超出部分 = 主题/成长溢价，回归压力方向」；
- SOTP 乐观区间上沿仍低于现价 → 是强卖出/回避信号（说明即使在最乐观分部倍数下也贵）；SOTP 中枢高于现价且区间含现价 → 合理偏低估，配合龟龟轨决策。

**门控**：chart_qc 图18 映射 §6 + 平台型触发时图18 必须存在且嵌入；gate_all 增加 SOTP 门（触发后缺 `reports/sotp_输出.json` 或报告未引用 → FAIL）；非平台型跳过。

    - 龟龟不达标（R_eff < II，KK < 0）且券商偏多 → 评级「中性/观望（双轨：龟龟 R_eff X% < II Y%，KK=Z pct 不建仓；券商 N 家中 M 家买入）」（2026-08-15 贵州茅台即此情形：R_eff 2.94% < II 3.70%、KK=-0.76pct，券商 30/32 家买入）；
    - 双轨同向 → 正常定级，仍并列标注两轨依据。

    投资摘要与投资建议必须使用模板句式（高成长标的并列龟龟成长校准轨，2026-08-21 新增）：

    ```text
    评级：中性/观望（双轨+成长校准）
    - 龟龟轨(保守)：R_eff X%（trailing C 口径）、II Y%、KK Z pct → 不建仓，等待目标买入价 A 元以下 / 仓位建议 W%
    - 龟龟轨(成长校准)：C_fwd 前瞻盈利（来源）→ R*_fwd X%、KK_fwd Z pct、目标买入价_fwd B 元
        （成长验证买入区 [A, B]；升级触发：中报/季报归母 ≥ 阈值 且 现金流/合同负债同步确认，实际数据验证后才可升级主轨）
    - 券商轨：N 家覆盖、M 家买入，共识目标价 B 元（共识日期，须注明是否最新财报后）
    - 12M 目标价：概率加权 C 元（+x%），区间 [D, E]（三层表述：概率加权/方法合成/交叉区间，口径分离）
    ```

    **纪律**：龟龟为基本面纪律底线——R_eff ≤ II 时评级不得高于「中性/观望」，券商共识只作市场空间参考，不得推翻龟龟不建仓结论；目标价三层（概率加权 / 龟龟目标买入价 / 券商共识）禁止混用。**龟龟成长校准轨（forward）同样不得推翻保守轨不建仓结论**——只作"成长验证买入区"与升级触发参考，升级必须由实际数据（中报/季报/合同负债）验证触发，预测本身不构成升级。

### D2 证据强度分级

| 级别 | 定义 | 要求 |
|------|------|------|
| L1 | 单一来源定性 | 背景 |
| L2 | 多来源定性 | 趋势判断 |
| L3 | 单一来源量化 | 普通数字；同一数据生产方的转引（如今日酒价/新浪转引同一机构数据）**不计为多源**，实为 L3 |
| L4 | ≥2 个**独立数据生产方**直接验证的量化 | **核心论点最低要求**；同一生产方转引不算交叉验证（2026-08-15 定义收窄） |
| L5 | 一手调研/可复现模型 | 关键估值参数 |

### D3 模型与数据纪律

- 三表联动模型、参数可调、情景可切换、历史回溯误差公开
- 关键数字标注来源+日期；行业/同行数据双源；一手数据标注方法/样本/时间

### D4 写作纪律

- 结论先行、一页摘要、图表服务结论
- 每句断言可溯源；不确定处标注"估计/假设/待验证"
- 禁用绝对化措辞（不说"市场从未……"，说"样本期内市场……"）

### G2 复验协议（建议 1 个季度后执行，公司披露密集期优先）

2. 核对公司公告（季报/年报/业绩预告/月度经营数据）与行业数据（监管/行业协会/同行）；
3. 逐项填写台账“实际值/偏差/归因”；单项偏差 >15% 或触发翻转点 → 更新滚动预测与评级；
4. 将偏差归因到方法论环节（数据接口、审计规则、预测校准、估值框架、穿透回报率、结论纪律），写入 skill 迭代日志；
