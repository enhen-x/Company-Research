# 研究专题：行业估值、指引订单、驱动预测与反方验证

本文件供 V3 技能内按需读取。它定义重复研究的内容契约与章节映射，不创建第二套报告结构。主报告仍严格采用 `report-template.md` 中的十章、小节标题与图号；专题结果写入对应现有章节。机器结果可由 `scripts/research_topics.py` 生成，正文以 Markdown 为唯一源，不生成逐专题 Markdown 或第二份研究报告。

## 1. 运行和输出约定

- 统一专题输入：`input/研究模型.json`，`schema_version=1`，顶层包括 `facts`、`assumptions`、`industry`、`guidance`、`orders`、`forecast`、`theses`、`decision`，并明确 `as_of`。事实使用 `facts.entity` 与 `facts.records` 登记数值、单位、期间和可定位来源，以 `source_ref` / `{ref: ID}` 引用；已解析引用不等于已核实事实。行业枚举、字段类型、必填项、引用方式以 `scripts/research_models.py`、`scripts/research_topics.py` 当前校验为准；不在报告里抄写另一份可能漂移的 JSON schema。
- 统一运行接口：Python 调用 `evaluate_topics(config, as_of=None)`；命令行读取批次输入并输出 `reports/研究模型_输出.json`。输出通过临时文件原子替换，输入缺失、字段错误、数据不足与研究不适用要区分并给出机器可读原因。
- 专题检查结果仅说明输入是否足以支持规定的研究检查，不等于预测或投资结论正确。输入不完整时标记 `INCOMPLETE` 并列出缺项；基础报告仍可继续，不能用占位值强行通过。
- 非适用模块标记 `NOT_APPLICABLE` 并说明经济模型原因；适用但资料不足标记 `INCOMPLETE`。显式零与 `null`/未取得分开；不会为缺失的指引、订单、共识、取消率、概率或模型假设自动填数。
- 事实与假设要保留来源、日期、期间、实体/分部、单位/币种、合并范围和计算口径。机器计算使用有限数值，口径不兼容时停止比较并报告原因。
- 相同输入重复运行应得到相同结果；脚本不得访问网络、等待人工输入或无上限重试。批次仅生成一份输入和一份 JSON 输出；图表继续由原图表流水线按固定图号生成，不另造专题图、汇总 Markdown、CSV 或临时报告。

## 2. 行业经济模型与估值选型

### 2.1 选择步骤

1. 在 §2.2 说明行业价值链、供需结构、资本强度、监管约束、周期与生命周期。按未来 3–5 年预计价值贡献最高的业务确定主经济模型；不要仅凭公司自称的行业分类选方法。
2. 对每个主要业务分别列收入/利润来源、现金转化、增长/资本需求和主要 KPI。次要业务只有在其现金流、资本风险或估值方法会改变集团结论时再独立拆分；若多个业务有不同经济特征或重要利润池，进入现有 §6.2 SOTP。
3. 在 §6.1 简述主估值方法、交叉验证方法、关键输入与限制。方法可标“适用”“不适用”或“资料不足”。PE、PB、DCF、SOTP及其他方法均按行业和数据选用；不得为填表强算不适用的模型。
4. 反向估值与正向估值使用相同方法、现金流/价值口径和估值时点，说明固定了哪些变量、反推出哪一个变量。一个市场价格在给定其他假设后只能反解一个未知数；不得宣称唯一解出多个经营假设。
5. 对照同行时，核对主营结构、阶段、市场、财年、币种、企业/股权口径和盈利周期。样本无法匹配时缩小或取消倍数比较并说明局限，不因固定同行数量扭曲样本。
6. 本矩阵是选择提示，不是自动估值引擎。脚本能提供的方法结果与分析师判断分开陈述；没有已验证数值模型时只能给方法框架或数据不足结论。

### 2.2 行业方法参考矩阵

| 经济模型/阶段 | 主方法候选 | 交叉验证 | 关键驱动与禁用边界 |
|---|---|---|---|
| 项目施工/工业制造 | 正常化中周期盈利倍数（可比 EV/EBITDA）或可支持的现金流模型；混业按 SOTP | 周期均值、反向估值、资产/服务分部对比 | 订单质量、履约、利用率、成本、营运资本、回款。禁止峰值利润×峰值倍数；施工与收费运营资产分开，特许经营期限需显式建模。源仓没有独立施工估值引擎。 |
| 金属矿业 | 生产矿山逐矿山有限寿命 DCF 汇总 NAV | 中周期 EV/EBITDA、历史 P/NAV、重置价值和商品价格敏感性 | 储量/寿命、品位、回收率、实现价格、AISC、维持资本开支、税费与闭矿责任。矿山寿命结束后不得默认永续；勘探资产单列风险调整期权，不放进生产资产基准 DCF，勘探型公司不以生产资产 DCF 为主。 |
| 能源 | 上游按资产 NAV；炼化用中周期现金流；中游按已签合同现金流；综合集团 SOTP | 反向 NAV/DCF、正常化现金流倍数和价格情景 | 储量/递减、实现价、维持资本开支、炼化价差、吞吐量/费率、套保与弃置义务。不同环节不得混用估值倍数。 |
| 消费品牌/门店 | 正常化 PE、DCF/FCF；门店成熟价值与新增门店 NPV | 复购、单位经济、门店成熟曲线、品牌/分部 SOTP | 销量、价格、产品组合、促销、复购、开闭店、蚕食和维护资本开支。周期性高毛利不能当作永久稳态；新开门店不能套成熟门店经济性。 |
| SaaS | DCF/反向 DCF；早期可用受利润率和现金转化约束的 EV/ARR 或 EV/收入 | Rule of 40、留存、获客回收期、成熟期现金流 | ARR 增长/流失、毛利率、获客效率、SBC真实成本和稀释。一次性许可、咨询或硬件不套用 SaaS 倍数；亏损与高再投资业务不以 EPV 为主。 |
| 互联网平台/多业务软件 | 成熟业务 DCF 与新业务单位经济情景结合 SOTP | 反向经营假设、扣除SBC后的自由现金流倍数 | 用户/交易量×变现率、业务留存、获客投入和资本回报。不同业务不能用单一 PE；成长性资本开支不可无条件加回。 |
| 银行 | P/TBV 对应可持续 ROTCE；股权剩余收益或 DDM | 正常化 P/E；反推 ROTCE、信用成本和股权资本成本 | 资本充足率、跨周期回报、存款成本、信用成本和可分配资本。禁止普通企业 FCFF/WACC、EV/EBITDA 和一般 ROIC 硬套；低 P/TBV 不自动代表低估。 |
| 保险 | 财险按 P/B–正常化 ROE、股权剩余收益/DDM；寿险按调整后内含价值和 VNB；经纪业务按其服务现金流估值 | 承保/利率压力、可分配现金、内含价值假设审计 | 综合成本率、巨灾/准备金、VNB、CSM、保证成本、退保、久期及资本要求。区分保险内含价值 EV 与企业价值 EV；经纪业务倍数不推广到承保主体。 |
| 权益 REIT | 物业 NAV 与 P/AFFO | AFFO现金流/交易资本化率；仅租约长、增长稳定的组合可用 DDM | NOI、出租率、租金、维护资本开支、资本化率及再融资。净利润/股息率不能替代估值；不同租约阶段和物业类别分开。每股 NAV =（物业 NAV + 其他资产 − 净债务及其他优先索取）/稀释股数。 |
| mREIT/地产开发 | mREIT 可用 P/B 并结合净息差/久期；开发商须另建销售回款、偿债和资产价值模型 | 利率、提前还款、融资情景；开发商核对去化和现金回笼 | 两者与权益 REIT 区分。不能把权益 REIT 的 P/AFFO 或 AFFO-DCF 套给开发商；数据不足时不假称存在成熟行业路由。 |
| 受监管公用事业/发电 | 受监管业务按 rate base、实际 ROE、资本结构及融资稀释驱动 DDM/DCF；竞争性发电独立建模；混业 SOTP | P/B–实际ROE、正常化 PE、重置/容量价值 | allowed ROE 不等于实际 ROE；监管资产不保证可回收，高资本开支不保证每股价值上升。竞争性发电不得套受监管业务的永续回报。 |

矩阵借鉴行业方法规则，不声称来源已提供可直接运行的估值模块。特别是有限寿命 NAV、银行股权剩余收益、寿险 EV/VNB、REIT NAV/AFFO、rate-base 融资均需单独定义输入、公式、价值桥并验证。通用永续 DCF 不能替代有限资产寿命模型，企业 EVA 不能替代银行股权剩余收益。

## 3. 管理层指引版本与兑现

在 §3.4/§3.5 记录证据，§5 用于挑战预测，§8 建立验证时点，§9 检查下修或口径变更。管理层指引是证据，不等于独立基准预测。

- 区分正式财务指引/业绩预告、经营预算目标、长期战略目标与口头展望。指引、分析师一致预期和独立预测分开保存并注明日期；A/H股未必定期发布数字指引，缺失时标明未披露，不凑季度样本。
- 逐版本记录原文出处及页码/发言人、发布日期、适用财年/季度、实体/分部、指标定义、区间上下沿或方向、币种/单位、合并范围、GAAP/调整后口径及适用假设。版本只追加，保留初始、维持、上调、下调、撤回、到期状态及原因。
- 兑现复核分别比较初始指引和结果公布前最后有效的指引，另记实际值；不可比口径不得硬算命中率。区间先判实际是否落入区间，再报告必要的偏离；近零或负分母不用普通百分比误差。将发布距目标期时间列出，避免把期后预告算作长期预测能力。
- 结合已实现进度、季节性、剩余季度隐含要求、订单/产能/价格与成本判断兑现难度，不能线性平摊全年目标或用最新上调覆盖初始失准。
- 指引下沿如被既有龟龟成长校准规则用作前瞻盈利证据，仍须满足该规则的历史增速、盈利率、证据和实际现金验证条件；预测本身不升级主轨。**R* 保守轨仍是默认纪律；现金验证失败降级 GG；成长校准不推翻保守轨。**

## 4. 订单存量与履约、利润和现金

适用于订单确实提供未来收入可见度的业务。先在 §2/§3 判断经济相关性，再判断数据是否可得。非订单型业务标记不适用；适用但披露不足标记数据不足，均不推定为零，不以缺少backlog使公司自动失败。

- 区分期末在手订单（存量）与本期新签（流量），并将生效且具约束力合同、可取消订单、框架协议/意向、未授标项目分列。分清标的销售订单、客户资本开支/采购计划和行业订单。RPO/cRPO、ARR、billings、合同负债按公司披露定义记录，不能直接视为相同指标或相加；合同负债也不等于全部订单。
- 记录统计日期/期间、定义、分部、币种、含税与否、合并或权益口径、总额/净额及来源。检查集团与子公司/JV重复、累计和单季混用、框架总额与实际下单重叠、RPO与cRPO重叠，以及已确认收入重复保留在剩余订单内。
- 同口径订单滚动桥：期初存量 + 新纳入 + 汇率/并购/范围变动 − 履约销减 − 取消 = 期末存量。需注明公司对履约销减定义；履约不必等于会计收入。未披露项保留未知/残差，不倒造项目。若新签订单已经扣掉取消，不再重复扣减。
- 结合订单批次、交付年度、客户集中、产能、验收、固定价/调价条款、延期、账龄、融资条件和毛利率评估转化。未知取消率或毛利率不假设为零取消/零成本，也不设 100% 转化。情景区间必须说明证据；缺历史转化样本不得给精确概率。
- 预测顺序分开：订单/履约→会计收入→毛利和费用→净利润/EPS；再单独建现金桥，包括预收、里程碑、验收、质保金、退款、应收/合同资产、营运资本与资本开支。§4.2核查合同资产/负债、应收及回款。订单已进入预测现金流的价值不得再作为资产加进估值。

## 5. 驱动预测、预期差与反方验证

### 5.1 驱动预测

在 §5.1–§5.4 按主经济模型选驱动，使用来源明确的历史事实和假设，展示基期、期间、预测方法、区间、可跟踪指标与失效条件。可能的驱动包括量/价/组合、门店/客户/留存、订单交付、商品价格/利用率、银行资产收益率/信用成本、保险承保和利差等。非金融企业按适用程度连接收入、利润、资本投入和现金流；金融企业用资本、信用/承保及可分配资本约束。不得用单一行业模板强套所有公司。

驱动模型必须明确毛利与费用是否已含折旧摊销，禁止重复扣减；混合口径需拆分成本与费用中的折旧。亏损时有税率不能自动确认税收利益，须显式说明是否可实现。比率统一为小数，未知口径或数据缺失保留 `null + INCOMPLETE`。

投入资本可在同一输入的 `decision.capital_metrics.invested_capital_bridge` 登记期初/期末经营桥和融资桥，字段及支持的会计政策见 `scripts/capital_metrics.py`。该可选双桥要求同一实体、单位、币种、合并范围、会计基础，明确商誉、资本化租赁、少数权益、受限资金、并购和NOPAT调整，核对真实时点及前后可比年度NOPAT；分项未知不补零，对账失败不供正常ROIC/ROIIC。旧资本输入仍兼容，但双桥标记 `NOT_ASSESSED`。金融业务使用专用资本约束；`reinvestment_check` 仅在桥与稳态假设明确时作增长互验，若ROIIC与同一资本增量构成恒等式，会标明它不能提供独立验证。结果用于 §4/§5/§6，不增加报告章节或文件。

指引、共识和独立预测并列表述，但不将它们视为独立事实或重复加权。三情景须有可区分且有依据的变量与触发事件；概率只能在情景互斥且穷尽、且有合理证据时归一加权。数据不足时保留情景但说明不可量化部分。现实检查至少覆盖历史/周期带、剩余期间目标、产能/份额、资金与稀释、订单质量和现金转化。

### 5.2 反向估值与市场隐含预期

§6采用该行业适用的方法反推市场价格所要求的一个关键经营变量（如银行可反推 ROTCE/信用成本，生产矿业可反推商品实现价/成本，订单行业可反推转化率/利润率）。清楚列出固定假设、估值口径及模型版本；和独立基准预测对比并说明差异如何被验证。不把反向结果误称共识，也不以过多不同名称的估值方法重复计为独立证据。

当前可执行边界：独立估值引擎的 `five_year_dcf` 已与稳定DCF共用五年现金流函数，固定基期现金流、折现率、终值增长和价值桥，有限次二分仅反解初始增长，输出重建误差与无解状态；Gordon反解只作稳态诊断。专题中的银行稳态ROTCE反解也不能替代完整资本预测。矿山实现价、订单转化率及其他任意行业驱动反解尚须单独模型，不应把方法要求当作已实现能力。执行与口径契约见 `strategies/valuation/coordinator.md`。

### 5.3 反方验证

§9针对支撑估值和评级的承重论点主动寻找最强相反证据，而非罗列泛泛风险。建议形成如下分析表，证据需追溯来源并说明可靠性：

| 承重论点 | 最强反方证据 | 对应假设/估值影响 | 处置及理由 | 触发阈值/复核时点 | 决策变化 |
|---|---|---|---|---|---|
| 明确写出可证伪论点 | 相反事实或可观察数据 | 参数、情景、价值区间中哪一项变化 | 接纳/部分接纳/暂不采纳/未解决；说明依据 | 对应第8章指标 | 调整预测/估值/仓位/观望或退出 |

对未解决的重大反证须降低结论强度、限制动作或列为待研究；不得因模板字段已填就自动通过。若反方证据未改变结论，解释其为何不足。观望论点同样列出支持上行的证伪条件。

### 5.4 跟踪闭环与报告映射

冻结预测版本及其输入指纹，以 §8.2 记录基线、阈值、来源、验证日期、实际结果和动作。财报/公告/行业数据更新后，按原口径比较并归因到外部信息变化、原假设误差或模型错误。摘要只提炼 §3–§9 的已论证结果，不在 §1 添加新假设。专题只改变对应章节内容和证据，不更改报告章节、子章节或图号。
