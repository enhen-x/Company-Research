# Company Research（公司证券调研流水线）

## 概述

一句话触发 → 自动拉数 → 数据审计 → 八步分析 → 交叉验证 → 评级结论。

用户只需给出 `调研 <公司名或股票代码>`（如“调研 温氏股份”“调研 300498”），本技能自动完成 B1-B3 阶段（立项、拉数、审计），再由 Agent 按券商深度标准完成 B4-B6（八步分析、交叉验证、结论输出）。

## 与 securities-analysis、guigui-valuation-report 的配合（分析时必须同时调用）

分析上市公司时，**必须同时加载并使用 `securities-analysis` 与 `guigui-valuation-report` 两个技能**：

- 本技能（company-research）负责：自动化流水线、数据拉取与审计、脚本执行、报告产出物管理。
- securities-analysis 负责：格雷厄姆/胡克方法论、八步分析框架、四种估值方法（DCF/相对价值/并购/LBO）、研究报告结构标准。
- guigui-valuation-report 负责：**基本面穿透回报率估值**（Phase 3）——Owner Earnings、真实可支配现金 AA、粗算 R / 精算 GG、门槛 II、安全边际 KK、目标买入价/门槛价格、外推可信度、价值陷阱排查、业绩下滑敏感性、绝对估值与仓位建议；脚本 `scripts/calc_penetration_return.py` 确定性计算。

分工原则：**数据与执行走本技能，券商方法与报告标准走 securities-analysis，穿透回报率与仓位纪律走 guigui-valuation-report**。任一技能单独触发时，主动加载另外两个；三者口径冲突时，以各自方法论文件（`references/methodology.md`）为准并在报告中并列披露。

**报告标准冲突处理（强制）**：三技能协同分析时的报告标准冲突一律按 `references/framework.md` §D0《三技能协同报告标准决议》（2026-08-12 拍板）执行——十部分主干 / GG 主导+双锚 / 三情景+敏感性双轨 / 并集 18 张图表 / G1-G21 门控，不再现场折中。

## 工作流程（六阶段）

### B1 解析与立项（自动）

解析公司名/代码 → 推断市场前缀（6/9→SH，0/3→SZ，4/8/92→BJ）→ 创建项目目录。

**文件夹命名规范（强制）**：每次新建项目文件夹必须为 `<市场>.<代码> <公司名>`（如 `SZ.300498 温氏股份`），**代码+名称缺一不可**；任一缺失由脚本自动解析（akshare 正/反向查询），解析失败则报错退出并提示补充，禁止用代码代替名称（如 `SZ.300498 300498`）。

**标准文件架构（强制，脚本自动创建，不得改变顶层结构）**：
```
<市场>.<代码> <公司名>/
├── 财报更新验证.md        # ★ 跨批次汇总（v2 批次档案版：回测汇总表 + 每批次预测-实际-归因-迭代档案；模板见 references/project-structure-v3.md §3）
├── <YYYY_MM_DD>/          # 每个分析批次（文件夹名=本次分析的实际日期，如 2026_08_15 仅为示例；新财报后新建，旧批次保留）
│   ├── README.md          # 总览：评级/目标价/核心逻辑/风险/交付状态
│   ├── ROADMAP.md         # B4-B6 八步路线图
│   ├── 交付清单.md         # ★ 交付物清单（B6 交付前逐项核对）
│   ├── data/              # 原始数据：拉取清单.json / 审计报告.html / *.csv
│   ├── input/             # 模型输入：穿透回报率_输入.json（guigui --config）
│   ├── scripts/           # 复验与图表脚本：verification.py / calc_penetration_return.py / analyze_*.py
│   └── reports/           # 主报告 MD+HTML / 图表/ / 穿透回报率_输出.json / 跟踪验证台账.md
└── <YYYY_MM_DD>/          # 下一批次（新财报后重新分析）
```

**放置规则**：数据只进 `data/`、模型输入只进 `input/`、分析脚本只进 `scripts/`、交付报告只进 `reports/`；图表 PNG 统一 `reports/图表/图NN_*.png`，交互图统一 `<公司名>_<代码>_图表.html`。B1 同时生成 `交付清单.md`（第一节：B1-B3 自动产出；第二节：B4-B6 交付物；第三节：成稿门控）。

### B2 数据拉取（自动，akshare）

**先探测后拉取（强制）**：

1. 立项后先运行 `python scripts/probe_sources.py <代码> --out <项目>/data`（约 2 分钟）→ 生成 `data/源探测.json`，列出各数据源（东财/腾讯/新浪）实时连通性与 akshare 接口存在性；
2. 拉数统一走适配层 `python scripts/fetch_with_fallback.py <代码> --out <项目>/data`——每个数据项按候选源自动切换（如日线：东财 stock_zh_a_hist 失败自动换腾讯 stock_zh_a_hist_tx），每次调用记录（源/状态/行数/失败原因）自动写入 `data/拉取清单.json`；接口在当前 akshare 版本缺失的直接标注 MISS，不报错中断；
3. 已知源坑位（符号格式/接口缺失/SSL 故障/复权口径/单季表语义）见 `references/data-source-notes.md`，每次分析先浏览，遇新坑按第八节协议补充。

资产负债表、利润表、现金流量表（按报告期）、主要财务指标（报告期+单季度）、日线行情（不复权+前复权）、公司概况/股本/总市值、**分红送配记录**。行业特有数据由 Agent 补充并双源交叉验证；网络失败不中断，缺失项在审计报告中标注。

**行业成本—价格数据（B2.2，乳制品等成本驱动行业必做）**：伊利股份等乳企必须运行 `scripts/fetch_industry_cost_price.py --dir . --profile dairy` 生成 `data/行业成本价格.csv`（生鲜乳收购价 role=cost + 鲜奶零售价 role=price，可加 volume 产量/存栏序列与 margin 价差序列，≥3 年真实历史、双源交叉验证）并审计通过；报告 §2 宏观与行业 必须嵌入 **图16 行业成本与价格走势**（analyze_charts.py v3：供需下方面板 + 成本/价格原始值双轴 + 价差示意，**每序列只画自身观测点无断点、横坐标稀疏刻度不重合**，禁止只用指数化单轴），解读供需、成本—价格传导与毛利走向。

穿透回报率估值（龟龟 Phase 3）必需数据：① 分红送配记录（支付率法2与DPS校验，接口 `ak.stock_fhps_detail_em`，失败时用现金流量表"分配股利支付的现金"降级）；② 10年复权+不复权行情（股价分位与基准价锚）；③ 无风险利率 Rf（中国10年期国债，A股；港股/美股用当地Rf），缺失时用估计值并必须进 Warnings。

### B3 数据审计（自动）

- 完整性：各表行数、年份覆盖（目标 ≥10 年）、最新报告期 ≤6 个月
- 一致性：归母净利 vs EPS×股本、归母权益 vs BPS×股本（容差 ±10%）；现金流审计同时检查 OCF/净利、资本开支、营运资本、应付账款和加盟商结算，不能仅以 OCF/净利含金量下结论
- 异常值：营收/净利同比突变（**>50%**）或**符号反转**、BPS≤0、重复报告期、缺失关键字段——每项须有合理解释（口径/重组/周期），无法解释计入 Warnings
- 分红一致性：近 3 年 DPS×股本（按除权除息日归集）vs 分配股利支付的现金（容差 ±10%）
- 支付率双法校验：法1 vs 法2 近 3 年均值，偏差 >5pct 排除法1；DPS **≥3 年完全相同**才触发"疑似填充错误"（2 年相同+支付率稳定=平滑分红政策，非错误）
- OCF 季节性集中度：近 3 年 Q4 单季占比 >80% 标注；连续多年 >80% 判定常态集中（注明原因），单年突升需调查
- 行业成本—价格审计（行业适用，B2.2）：`data/行业成本价格_审计.json` 无 FAIL（CSV 契约、cost+price 双序列、每序列 ≥3 行、来源/来源日期齐全）；独立来源 <2 计 Warnings 并在报告标注

门控：全部通过→继续；有警告→继续但结论标注数据局限；有错误或财报 <3 年→暂停并降级为初筛报告。

### B4 八步分析（Agent）

宏观 → 行业 → 公司 → 财务 → 预测 → 估值 → 投资建议 → 综合报告。核心论点证据级别 ≥ L4（多来源交叉验证量化）；沿用项目模式 `scripts/analyze_*.py` + `reports/*.html`；关键数字标注来源+日期。

> **输出边界（强制）**：B4 八步为**纯计算/分析层**——只产出可复算数字、图表与 `scripts/analyze_*.py`/`reports/*.html` 分析文件，**不产成文正文**；步骤7 仅出数字表（评级/三情景目标价矩阵/龟龟目标买入价/门槛价格/仓位推导链的数字），**禁止写成文句子**；步骤8「综合报告」仅为**过程终点汇总**，不独立成文，归入 B6.2。所有文案级输出（评级/目标价/投资建议/综合报告/摘要）一律在 **B6.2 唯一成文点** 成文（按 framework §D1 十部分）。

**必备分析模块（缺一不可，可视化标准见下）：**

1. **分部营收**：按行业/产品/地区口径给出各业务板块收入占比与增速；披露口径变更时必须新旧口径并列并明确标注不可跨期直接比较。
2. **单位产出成本**：构建“单票/单吨/单平米/单客”单位经济学（收入、成本、毛利、净利），展示历史趋势（≥3 年+最近季度），并与同行对比；跨公司口径差异（如含/不含派费）必须标注。
3. **盈利预测历史支撑**：每个预测假设都要有历史数据锚（如预测单票净利 ≤ 最近已实现季度值）、同行对标（净利率低于可比龙头）与业绩预告交叉验证；明确“为何不是曲棍球棒”。模型必须形成“件量 × 单票收入 = 收入；单票成本/净利率、期间费用、税率、股本 → 归母净利 → EPS”的驱动桥。行业收入增速高于件量增速只能先解释为阶段性单票收入、结构或结算口径改善，不能直接写成长期定价权或“反内卷已确立”。公司件量还要与行业件量联动，反推出隐含市占率并检查产能、资本开支和价格投入是否匹配；H1 利润覆盖率必须按预告区间与全年预测重新计算；Q4 等单季高盈利须经季节性和异常项复核后才能作为年度盈利锚。**周期/修复类公司必须加“周期均值窗口敏感性”**：按 5Y/8Y/10Y/最近 2Y/最近半年等窗口计算平均盈利与平均单位净利，展示不同窗口 × 估值档（9/11/13x）对应的目标价区间，并解释报告采用哪个锚及原因。
4. **估值双锚 + 分阶段估值带**：必须同时用 PE（仅盈利正常期）与 PB（跨周期）双指标；历史估值带按行业发展阶段分段标注（成长/出清/修复/成熟），阶段边界必须有量、价、盈利、政策或竞争格局依据，不能用几个月数据事后定义“成熟期”。评价用“本阶段内百分位”为主、全历史分位为辅；说明 PE 在亏损/微利期失真的原因。**DCF 必须先明确 FCFE 或 FCFF：FCFE 从归母净利润出发、使用股权资本成本且不再扣净债务；FCFF 从 EBIT/NOPAT 出发、使用 WACC 且终值后扣净债务。** FCF 必须由利润、D&A、ΔWC、OCF、资本开支桥接，披露终值占 DCF 总价值比例并给 FCF 下行情景；终值占比过高时降低 DCF 结论权重。**同行对比必须统一估值日期、盈利年度、TTM/静态/前瞻、归母/扣非、PB 净资产日期及跨市场汇率/币种**，并附**同行历史估值对比图**（同一坐标系：年度 PE/PB 折线 + 当前点；当前点与正文会计口径一致，无法统一时标注“历史参考口径”）。
5. **目标价分情况展示与安全边际**：按情景（悲观/基准/乐观）给出目标价矩阵与区间；概率须说明事件定义和估计方法，风险概率不能直接相加，且每个风险情景都要映射到件量、价格、利润率/现金流、估值倍数和目标价。按格雷厄姆框架量化安全边际（价值折价、净资产保护、风险不对称/盈亏比、边界声明）；PE、PB、DCF 和情景估值若共用同一盈利假设，不得宣称为“多个独立安全边际”，必须披露假设重叠。
6. **治理与关联交易量化**：股权结构（大股东/实控人状态）、股权纠纷/减持等治理风险要有事实与跟踪路径；重大关联交易（并购/资产收购）必须量化交易对价、现金支付、可辨认净资产、新增商誉、占净资产比例、分部收入/毛利/利润、整合成本、并表里程碑，并说明对 FCFE、净债务和商誉减值的影响。
7. **风险概率与资本结构方法学**：每个风险给出概率，并注明方法（历史频率/情景推演/趋势外推/规模约束/事件驱动）和触发跟踪条件；明确“主观概率，非精算”，不直接相加。负债率不能直接等同于高杠杆，必须拆分有息债务、租赁负债和经营性负债，结合利息覆盖、期限结构、现金及经营现金流判断偿债压力；OCF/净利润高也不能直接等同于盈利质量高。
8. **预测与估值逻辑审计**：成稿前反向复算“事实 → 假设 → 模型 → 目标价 → 评级”的因果链；所有表格最低值、正文尾部目标价、风险回撤和概率加权目标价必须可由同一组输入复算，发现断链时降级表述为“待验证假设”。
9. **穿透回报率估值（龟龟 Phase 3，基本面分析必做）**：按 `guigui-valuation-report` 方法论输出——Owner Earnings（H=D×G，G需依据近3年Capex/D&A）、真实可支配现金 AA（默认近2年均值 AA_2y，5年均值 AA_all 对比）、支付率 M（法2=分配现金/归母净利润，近3年均值；DPS连续多年相同禁止用法1）、粗算 R=C×M/市值、精算 GG=AA×M/市值、粗算偏差 HH=R−GG（|HH|≥2pct 需专项调查）、门槛 II=max(3.5%, Rf+2%)、安全边际 KK=GG−II（弱周期不修正）、目标买入价=股价×GG/II、门槛价格=股价×II/GG、5维外推可信度、5项价值陷阱排查、业绩下滑敏感性表（单年×0.7~×1.0 与逐年×0.9^n，含 k*）与绝对估值（EV/EBITDA、扣除现金PE、FCF收益率、净负债/EBITDA、商誉/总资产、股息率、基准价三锚）。**必须运行** `~/.codex/skills/guigui-valuation-report/scripts/calc_penetration_return.py --config 输入.json` 复算，禁止手算；输入JSON字段与口径见该脚本头部文档。`--json` 输出为**纯 JSON**（人类可读文本走 stderr），写入 `reports/穿透回报率_输出.json`；**G 敏感性网格（g_grid）由脚本默认输出**，报告中 G 网格行禁止手写。仓位推导链（KK→可信度→陷阱风险）缺一环必须降档或说明；GG≤II 时不建仓，输出观望/卖出。

- **因果链**：收入增速、件量增速、单票收入/成本、利润率和 EPS 的关系已拆开；没有把单一期间的价差改善直接升级为长期定价权。
- **经营闭环**：公司件量、行业件量和隐含市占率相互一致；市占率提升的资本开支、网络和价格投入有证据支持。
- **时间口径**：H1 覆盖率已算术复核，Q4 峰值已做季节性调整；季度、年度和 TTM 不混用。
- **DCF 口径**：FCFE/FCFF 只选一种，现金流桥可回溯到三表，终值占比、净债务处理和敏感性矩阵齐全。
- **可比口径**：估值日期、盈利年度、归母/扣非、TTM/静态/前瞻、PB 净资产日期和跨市场汇率均已统一；历史阶段边界有基本面依据。
- **安全边际**：已披露 PE、PB、DCF、情景估值之间的共同盈利假设，未把相关方法误写为独立安全边际。
- **风险复算**：情景概率、触发事件、盈利影响、估值倍数和目标价能逐项对应；尾部压力测试的最低值与正文一致。
- **并购与财务质量**：并购对价、现金支付、商誉、整合成本和 FCFE/净债务影响已量化；负债按有息、租赁、经营性拆分，OCF 质量已结合资本开支和营运资本判断。
- **穿透回报率口径**：支付率 M 用近3年均值（法2）、AA 默认 AA_2y、现金用狭义口径、Rf 标注来源/估计；\|HH\|<2pct 已校验；DPS 连续多年相同已排除法1。
- **仓位纪律**：仓位建议必须给出 "KK → 可信度 → 陷阱风险" 完整推导链；GG≤II 时不得建仓；目标买入价与券商目标价口径分离标注（前者是 GG 降至门槛对应的最高买价，后者是12个月盈利与倍数外推）。
